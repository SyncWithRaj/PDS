6. Bottleneck Identification & Mitigation Strategies

⚠️ High write contention on viral user accounts during timeline fanout

Mitigation Strategy: Implemented hybrid fanout strategy where followers > 10,000 use pull-on-read while standard users use push-on-write via Kafka workers.

⚠️ Graph traversal latency scaling non-linearly with deep relationship degrees

Mitigation Strategy: Configured Redis caching layer for hot friend graphs and limited graph query depth to 2 hops with indexed edge properties.

⚠️ WebSocket connection limits per gateway node under peak traffic spikes

Mitigation Strategy: Deployed horizontal auto-scaling WebSocket gateway pods behind a Network Load Balancer (NLB) with Redis cluster pub/sub sharding.

⚠️ [DEF-01] Use of AMQP / RabbitMQ Event Queue for automated PITR snapshots and backups introduces an unnecessary secondary messaging protocol alongside Kafka.

Mitigation Strategy: Standardize backup coordination and snapshot events directly onto the existing Apache Kafka event streaming backbone or AWS native backup policies.

⚠️ [DEF-02] Connection description notes WebSocket Gateway publishing chat messages via Kafka topic pub/sub in text, but flowchart indicates Redis backplane.

Mitigation Strategy: Align architectural documentation to explicitly specify the Redis Pub/Sub backplane as the primary transit layer for WebSocket cluster synchronization.
