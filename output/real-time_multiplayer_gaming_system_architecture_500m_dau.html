5. Architectural Trade-Off Analysis

Polyglot Persistence Layer

Chosen: OLTP Store + In-Memory Cache  |  Discarded: Single Monolithic Relational Database

Separating transactional persistence from an in-memory cache holding the 80/20 hot set (64 GB RAM) achieves sub-10ms read latency at 555 read QPS.

Asynchronous Event Streaming Backbone

Chosen: Distributed Kafka  |  Discarded: Direct Synchronous REST/gRPC Chained Calls

Decoupling write operations through an event bus protects downstream services from cascading failures under peak load, trading immediate consistency for high availability and fault isolation.

6. Bottleneck Identification & Mitigation Strategies

⚠️ Traffic Surges Exceeding Peak Concurrency (694 QPS)

Mitigation Strategy: Deployed on Kubernetes configured with Horizontal Pod Autoscaling (HPA) targeting ~150 pods, backed by edge rate limiting at the API Gateway.

⚠️ Single Point of Failure in Relational Database

Mitigation Strategy: Configured Multi-AZ Active-Active replication with automated failover and read replicas.

⚠️ Database Connection Pool Exhaustion on Flash Read Bursts

Mitigation Strategy: Deployed 6-node Redis Cluster absorbing ~80% of read volume in-memory.
